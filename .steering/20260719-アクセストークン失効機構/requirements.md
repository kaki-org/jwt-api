# 要求内容

## 概要

ログアウト時に発行済みアクセストークンを失効させる機構を導入する（Issue #1250 対応）。

## 背景

現状のログアウト（`AuthTokenController#destroy`）は `refresh_jti` の削除と Cookie 削除のみで、発行済みアクセストークンは有効期限（30分）まで有効なまま残る。トークンが盗難された場合、ログアウトしても最大30分間は保護リソース（`/api/v1/projects` 等）にアクセスできてしまう。Issue #1250 の対応案2「ユーザー側カウンタによるアクセストークン失効」を実装する。

## 実装対象の機能

### 1. トークンバージョンによるアクセストークン失効
- `users.token_version`（integer, not null, default 0）カラムを追加する
- アクセストークンの `ver` クレームに発行時点の `token_version` を埋め込む
- アクセストークン検証時に `ver` クレームとユーザーの現行 `token_version` を照合し、不一致なら失効済みとして 401 を返す
- ログアウト時（`User#forget`）に `token_version` をインクリメントし、発行済みアクセストークンを一括失効させる

### 2. 挙動の明文化
- SECURITY.md にログアウト時のトークン失効挙動を記載する

## 受け入れ条件

### トークンバージョンによるアクセストークン失効
- [ ] ログイン・リフレッシュで発行されるアクセストークンの payload に `ver` クレームが含まれる
- [ ] ログアウト後、ログアウト前に発行されたアクセストークンで保護リソースにアクセスすると 401 が返る
- [ ] ログアウト→再ログイン後、新しいアクセストークンでは保護リソースにアクセスできる
- [ ] `ver` クレームを持たない既存トークン（デプロイ前発行）は `token_version` が 0（初期値）のユーザーに限り有効（移行措置）
- [ ] 既存の RSpec がすべてパスする

### 挙動の明文化
- [ ] SECURITY.md にログアウト＝リフレッシュ停止＋アクセストークン失効である旨が記載されている

## 成功指標

- ログアウト後のアクセストークン悪用ウィンドウ（最大30分）がゼロになる
- rubocop / RSpec 全件グリーン

## スコープ外

以下はこのフェーズでは実装しません:

- トークンの denylist（jti 単位の個別失効）
- 全デバイス一括ログアウト API（token_version インクリメントの副次効果としては得られるが、専用エンドポイントは作らない）
- フロントエンド（front/）の変更（401 時の既存ハンドリングで対応可能なため不要）
- apidoc/openapi.yaml の変更（レスポンス形状に変更がないため不要）
